# Kia EV6 India 260430 — off-car port

This port targets `CVEV.IND.0000.V010.001.260430` only. It needs the India
hook map proposed in [HMG-API #295](https://github.com/Open-HMG/HMG-API/pull/295).
An official HMG-API version number alone does not imply that map is installed.

The owner confirmed wireless Android Auto and CarPlay, and Apple Maps/Google Maps
turns on the cockpit and HUD, with a separate Leafia-based India package. **This
HMG-API implementation has not been installed or tested in the car.** Other India
firmware versions and models are not enabled.

## Implementation

The stock apps stay unchanged; current upstream hooks supply projection behavior.
The existing Core, Audio and Utils CarPlay recipes match the captured India files.
Android Auto library MD5 `b794003497e7382b739a231cb1d2bf10` needs its own recipe.
It reuses the upstream AA bridge, with India imports and an independently compiled
string-constructor ABI adapter. The adapter uses the stock allocator pair so the
stock destructor can free its strings. All external addresses are relocated at
application time; the helper-to-bridge reference is segment-relative.

The NEMESIS descriptor conflicts with `codevalley.ev6.india.projection` to prevent
stacking this mod over the previously tested India package.

- SDK 1.1.0-rc.4 compilation and head-unit script checks passed.
- Upstream AA/CarPlay turn conversion, route-guidance reattach, AA support, audio
  concurrency and CN7NPE integration/packaging regressions passed. Other private
  regional fixtures were unavailable; their private native tests were skipped.
- Actual India stock plan/apply/settings-change/restore passed; system tree restored

  `onebin/cvev_in/featurexml.cfg` for the fixture.
- Actual SDK MemRecipe: 60 checks, including relocated segment addresses, guard
  rejection before writes, out-of-range allocation and failed-code-write behavior.
- ARM emulation: 20 constructor/destructor cases at two addresses, boundary lengths
  0, 1, 15, 16, 17, 126, 127, 128, 129, 255; allocator/free matching and buffer guards.
  Allocators are instrumented stubs; the destructor is from private stock.
- Three CarPlay recipes: in-memory results equal the file applicator's results on
  the actual India Core, Audio and Utils libraries.

These checks do not test the Android loader, phone protocol traffic, physical
cockpit/HUD or reboot recovery. Those remain vehicle acceptance work.

## Reproduce the India checks

Use the released HMG-API mod SDK and JDK. Set `HMGAPI_SDK` and
`INDIA_STOCK_LIBRARY` (path to the private stock `libautoreceiver_infobank.so`), then
run `sh wireless-carplay-aa/tools/india-tbt/test.sh`.

On Linux with clang-18, lld, llvm-objcopy-18 and qemu-arm-static:

```
cd wireless-carplay-aa/native/india-tbt
sh build.sh
python3 generate.py "$INDIA_STOCK_LIBRARY"
python3 arm-test.py "$INDIA_STOCK_LIBRARY"
```

The helper's table is at offset 0 and its Thumb entry is at offset 0xc. The recipe
embeds only the upstream bridge and our helper; no stock library is distributed.
